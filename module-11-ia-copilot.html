41.1 — IA, Machine Learning, IA générative : les distinguer

Fig. 41.1 — L'IA générative est un sous-ensemble du Machine Learning, lui-même un sous-ensemble de l'IA

LLM (Large Language Model)

Modèle entraîné sur d'immenses quantités de texte pour prédire la suite la plus probable d'une séquence de mots — c'est ce mécanisme de prédiction qui, à grande échelle, produit des réponses cohérentes, du code fonctionnel ou des résumés pertinents.

41.2 — Microsoft Copilot dans l'écosystème M365

Copilot s'intègre directement dans Word, Excel, Outlook, Teams et PowerPoint — il a accès (avec les permissions de l'utilisateur, respectant le RBAC du Module 5) aux données du tenant pour contextualiser ses réponses, contrairement à un chatbot public isolé.

42.1 — Copilot Studio : créer un agent conversationnel

Copilot Studio

Outil low-code (dans la lignée du Module 9) permettant de créer des agents conversationnels personnalisés — répondant aux questions fréquentes, déclenchant des actions (via connecteurs Power Automate), sans écrire de code d'IA.

Un agent se construit autour de sujets (thèmes de conversation), chacun avec des déclencheurs (phrases types de l'utilisateur) et des actions (réponse, appel de flux, escalade vers un humain).

42.2 — Intégration Copilot + Power Automate

Un agent Copilot Studio peut appeler un flux Power Automate en arrière-plan — par exemple, un employé demande "quel est le statut de ma demande de congés ?" et l'agent interroge la liste SharePoint (via un flux du Module 9) pour répondre en temps réel, sans intervention humaine.

42.3 — Prompt engineering pour l'IT

La qualité d'une réponse IA dépend directement de la qualité de l'instruction (prompt). Quelques principes utiles pour des cas d'usage IT :

  • Contexte explicite — préciser l'environnement (ex. "pour un script PowerShell ciblant Windows Server 2022")
  • Format attendu — demander explicitement un tableau, une liste, du code commenté
  • Contraintes — préciser les limites (ex. "sans dépendance externe", "compatible PowerShell 5.1")
  • Itération — affiner par des demandes de suivi plutôt que tout attendre d'un seul prompt
📁 Étude de cas — Hôtel

Agent Copilot Studio pour les demandes du personnel

Contexte : La chaîne hôtelière (suivie tout au long du parcours) reçoit de nombreuses questions répétitives du personnel sur les procédures internes (horaires, congés, accès aux outils).

Solution retenue : un agent Copilot Studio intégré à Teams, capable de répondre aux questions fréquentes à partir de la documentation interne (SharePoint du Module 5), d'interroger le statut d'une demande de congés via un flux Power Automate, et d'escalader vers les RH pour les questions plus complexes qu'il ne sait pas traiter.

43.1 — Génération et débogage de scripts

L'IA générative accélère l'écriture de scripts PowerShell (Module 7) ou Python (Module 8) — mais ne remplace jamais la compréhension : chaque script généré doit être lu, compris et testé avant exécution en production. L'IA excelle particulièrement pour expliquer une erreur ou proposer une première ébauche à affiner.

43.2 — Automatisation de rapports avec l'IA

Combiné à Power Automate (Module 9) ou un script Python (Module 8), un appel à un modèle IA peut résumer automatiquement un ensemble de données brutes en synthèse lisible — utile pour transformer les logs techniques du Module 10 en rapport compréhensible par une direction non technique.

43.3 — Détection d'anomalies (concepts)

Détection d'anomalies par IA

Les modèles de Machine Learning peuvent apprendre un comportement "normal" (trafic réseau, charge CPU) et signaler automatiquement les écarts significatifs — une extension moderne des alertes à seuil fixe vues avec Azure Monitor (Module 6), capable de détecter des schémas plus subtils qu'un simple dépassement de valeur.

43.4 — Chatbot de support IT

En combinant Copilot Studio (semaine 42) et une base de connaissance (documentation interne, tickets résolus), on peut construire un premier niveau de support IT automatisé qui répond aux questions courantes (mot de passe oublié, imprimante hors ligne) avant escalade vers un technicien humain.

📁 Étude de cas — Usine

Synthèse automatisée des logs de production par IA

Contexte : L'usine (suivie tout au long du parcours) génère des milliers de lignes de logs quotidiens depuis ses systèmes de supervision — illisibles pour la direction sans effort d'analyse technique.

Solution retenue : un script Python (Module 8) collecte les logs, puis un appel à un modèle IA générative produit une synthèse quotidienne en langage clair ("3 arrêts machine mineurs, aucun incident critique, tendance de température stable"), envoyée automatiquement via Power Automate (Module 9) — combinant les trois derniers modules du parcours.

44.1 — Risques de l'IA générative en entreprise

  • Hallucination — l'IA peut générer une information plausible mais fausse, avec la même confiance apparente qu'une information exacte
  • Fuite de données — envoyer des données confidentielles à un outil IA public non contractualisé viole potentiellement la confidentialité (retour au Module 5, DLP)
  • Biais — un modèle reflète les biais présents dans ses données d'entraînement
  • Dépendance excessive — accepter une sortie IA sans esprit critique

44.2 — Gouvernance des données et de l'IA

Une politique de gouvernance IA en entreprise définit typiquement : quels outils IA sont autorisés, quelles données peuvent (ou non) leur être soumises, qui est responsable de la vérification des sorties, et comment sont tracés les usages — un prolongement direct des politiques de conformité vues au Module 5 (Purview) et au Module 10 (SC-900).

Principe de responsabilité humaine

Quelle que soit la sophistication d'un outil IA, la responsabilité finale d'une décision ou d'une action reste humaine — l'IA assiste, elle ne décide pas seule dans un contexte professionnel engageant.

📁 Étude de cas — Administration publique

Charte d'usage de l'IA générative pour la mairie

Contexte : La mairie (suivie tout au long du parcours) souhaite encadrer l'usage de l'IA générative par ses agents, notamment pour éviter que des données citoyennes sensibles (Module 10, RGPD) ne soient transmises à des outils IA publics non contractualisés.

Charte mise en place : seul Copilot M365 (intégré au tenant, sous contrat de traitement des données) est autorisé pour tout traitement impliquant des données citoyennes ; les outils IA publics grand public restent réservés à des tâches génériques sans donnée sensible ; toute sortie IA utilisée dans un document officiel doit être relue et validée par un agent responsable, nommément identifié.
