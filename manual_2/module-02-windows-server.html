Windows Server

24 août 2026 → 20 septembre 2026 · Semaines 5–8 · 52 h prévues

Après avoir posé les bases réseau, ce module te fait entrer dans l'administration système Windows : installer un serveur, structurer un annuaire d'entreprise avec Active Directory, imposer des règles de sécurité via les GPO, et mettre en place les services de fichiers qu'utilise toute organisation au quotidien.

Objectifs de compétences du module
  • Installer Windows Server et choisir entre Server Core et Desktop Experience
  • Concevoir et déployer une structure Active Directory (forêt, domaine, OU, comptes)
  • Créer et appliquer des stratégies de groupe (GPO) pour sécuriser un parc de postes
  • Déployer des services de fichiers résilients (DFS), des sauvegardes et un accès bureau à distance
  • Surveiller la santé d'un serveur avec l'Observateur d'événements et le Moniteur de performances

Prérequis & matériel

Module 1 (Réseaux) recommandé, notamment DHCP/DNS. Tu auras besoin d'une VM Windows Server 2022 (évaluation gratuite 180 jours sur le site Microsoft) et idéalement d'une seconde VM cliente Windows pour tester la jonction au domaine.

5.1 — Éditions et modes d'installation

Windows Server existe en deux éditions principales : Standard (jusqu'à 2 machines virtuelles incluses par licence, adaptée aux PME) et Datacenter (virtualisation illimitée, adaptée aux grands environnements et à l'hyperconvergence). À l'installation, deux modes sont proposés :

Server Core

Installation minimale sans interface graphique, administrée en ligne de commande (PowerShell) ou à distance via Windows Admin Center. Surface d'attaque réduite, moins de correctifs à appliquer, moins de ressources consommées.

Desktop Experience

Installation complète avec interface graphique classique. Plus simple pour débuter, mais surface d'attaque plus large et plus de ressources consommées.

Bonne pratique professionnelle : en production, Server Core est recommandé pour les rôles d'infrastructure (contrôleur de domaine, DNS, DHCP). Desktop Experience reste pertinent pour l'apprentissage ou les serveurs nécessitant des logiciels tiers avec interface graphique.

5.2 — Rôles et fonctionnalités

Un rôle définit la fonction principale d'un serveur (ex. contrôleur de domaine, serveur DNS). Une fonctionnalité est un composant additionnel qui vient soutenir un rôle ou apporter un outil (ex. .NET Framework, outils d'administration distante).

Fig. 5.1 — Rôles Windows Server les plus courants en entreprise

5.3 — Méthodes d'administration

  • Server Manager — console graphique historique, gestion locale et multi-serveurs
  • PowerShell — administration en ligne de commande, scriptable et automatisable (approfondi au module 7)
  • Windows Admin Center — console web moderne installable gratuitement, remplace progressivement les anciens outils MMC, essentielle pour administrer du Server Core à distance
📁 Étude de cas — PME

Cabinet comptable de 12 employés (suite du Module 1)

Contexte : Le même cabinet comptable veut désormais centraliser l'authentification et le partage de fichiers. Un seul serveur physique, budget limité.

Choix retenu : Windows Server 2022 Standard en Desktop Experience pour ce premier déploiement (équipe encore en apprentissage, pas d'administrateur système dédié à temps plein). Un seul rôle critique pour commencer : AD DS avec DNS intégré.

Pourquoi pas Server Core ? Pour une PME sans équipe IT dédiée, la courbe d'apprentissage de l'administration 100% ligne de commande est un risque opérationnel plus grand que le bénéfice de sécurité — à réévaluer une fois l'équipe montée en compétence.

Laboratoire guidé 1 — Installation Windows Server 2022

Outil : Hyper-V/VirtualBox + ISO d'évaluation Microsoft · Durée : 50 min
  1. Télécharge l'ISO d'évaluation Windows Server 2022 (180 jours, gratuit) depuis le Centre d'évaluation Microsoft.
  2. Crée une VM avec au moins 2 vCPU, 4 Go de RAM, 60 Go de disque.
  3. Démarre l'installation, choisis Desktop Experience pour ce premier labo.
  4. Définis le mot de passe administrateur local.
  5. Une fois démarré, renomme le serveur (ex. SRV-CABINET-01) et configure une IP statique.
  6. Active les mises à jour automatiques et lance Windows Update.

Laboratoire guidé 2 — Promotion d'un contrôleur de domaine

Outil : la VM du labo précédent · Durée : 40 min
  1. Dans Server Manager, ajoute le rôle Services de domaine Active Directory (AD DS).
  2. Lance l'assistant de configuration post-déploiement.
  3. Choisis "Ajouter une nouvelle forêt" et définis le nom de domaine racine (ex. cabinet.local).
  4. Définis le niveau fonctionnel de la forêt et du domaine (Windows Server 2016 minimum recommandé).
  5. Laisse DNS s'installer automatiquement (coché par défaut).
  6. Termine l'assistant — le serveur redémarre et devient contrôleur de domaine.
  7. Vérifie avec Get-ADDomain en PowerShell.

Laboratoire guidé 3 — Création d'unités d'organisation (OU) et utilisateurs

Outil : Utilisateurs et ordinateurs Active Directory · Durée : 35 min
  1. Ouvre la console Utilisateurs et ordinateurs Active Directory.
  2. Crée trois OU : Direction, Comptabilite, Ordinateurs.
  3. Dans l'OU Comptabilité, crée 5 comptes utilisateurs avec convention de nommage prenom.nom.
  4. Force le changement de mot de passe à la première connexion pour chaque compte.
  5. Refais l'opération en PowerShell pour un utilisateur : 
    New-ADUser -Name "Jean Dupont" -SamAccountName "jean.dupont" -Path "OU=Comptabilite,DC=cabinet,DC=local" -Enabled $true -AccountPassword (ConvertTo-SecureString "P@ssw0rd!" -AsPlainText -Force)

6.1 — La hiérarchie Active Directory

Active Directory organise les ressources d'une entreprise selon une hiérarchie à plusieurs niveaux :

Fig. 6.1 — Hiérarchie Forêt → Domaine → Unités d'organisation → Objets

Forêt

Conteneur de plus haut niveau, peut contenir plusieurs domaines qui partagent un schéma et un catalogue global communs.

Domaine

Limite de sécurité et de réplication — regroupe les objets (utilisateurs, ordinateurs, groupes) qui partagent la même base d'annuaire.

Unité d'organisation (OU)

Conteneur logique permettant d'organiser les objets et surtout d'appliquer des GPO et de déléguer l'administration de façon ciblée.

6.2 — Groupes et délégation

Les groupes AD simplifient la gestion des permissions : on affecte les droits à un groupe plutôt qu'à chaque utilisateur individuellement (principe AGDLP — comptes dans des groupes globaux, dans des groupes locaux de domaine, auxquels on donne des Permissions).

  • Groupes de sécurité — utilisés pour attribuer des permissions
  • Groupes de distribution — utilisés uniquement pour la messagerie
  • Étendues — Domaine local, Global, Universel (portée croissante)

La délégation de contrôle permet de confier certaines tâches (ex. réinitialiser les mots de passe) à un utilisateur ou groupe sur une OU précise, sans en faire un administrateur du domaine — un principe clé de sécurité (moindre privilège).

6.3 — DNS intégré à Active Directory

Lorsque DNS est installé avec AD DS, les zones peuvent être stockées directement dans l'annuaire (zones intégrées à AD) plutôt que dans de simples fichiers texte. Avantage majeur : la réplication des enregistrements DNS se fait automatiquement entre tous les contrôleurs de domaine, avec sécurisation possible des mises à jour dynamiques (seuls les ordinateurs authentifiés peuvent mettre à jour leur propre enregistrement).

📁 Étude de cas — Hôtel

Structure Active Directory pour une chaîne de 3 hôtels

Contexte : Une petite chaîne hôtelière veut un seul annuaire pour ses 3 établissements, avec des équipes IT limitées et une administration déléguée localement à chaque hôtel.

Structure retenue : un domaine unique groupe-hotel.local, avec une OU par établissement (Hotel-Centre, Hotel-Gare, Hotel-Aeroport), chacune contenant ses propres sous-OU Utilisateurs/Ordinateurs/Groupes.

Délégation : le responsable IT de chaque hôtel reçoit une délégation de contrôle limitée à son OU (réinitialisation de mot de passe, gestion des comptes) — sans droits sur les autres établissements ni sur le domaine entier.

Laboratoire guidé — Gestion des groupes et délégation

Outil : Utilisateurs et ordinateurs AD · Durée : 35 min
  1. Crée un groupe de sécurité G-Comptabilite-RW (étendue Globale).
  2. Ajoute-y les 5 utilisateurs créés au labo précédent.
  3. Clic droit sur l'OU Comptabilité → Délégation de contrôle.
  4. Délègue la tâche "Réinitialiser les mots de passe utilisateur" à un utilisateur désigné "support local".
  5. Vérifie la délégation avec dsacls ou via l'onglet Sécurité avancée de l'OU.

Laboratoire guidé — Configuration de GPO (restrictions logicielles)

Outil : Gestion des stratégies de groupe · Durée : 35 min
  1. Ouvre la console Gestion des stratégies de groupe.
  2. Crée une nouvelle GPO liée à l'OU Comptabilité : GPO-Restriction-Logiciels.
  3. Dans Configuration Ordinateur → Stratégies → Paramètres Windows → Stratégies de restriction logicielle, crée une règle interdisant l'exécution depuis le dossier Téléchargements.
  4. Force la mise à jour sur un poste client : gpupdate /force.
  5. Vérifie l'application avec gpresult /r.

Laboratoire guidé — Configuration DNS intégré à AD

Outil : Gestionnaire DNS · Durée : 25 min
  1. Ouvre le Gestionnaire DNS sur le contrôleur de domaine.
  2. Vérifie que la zone cabinet.local est bien "Intégrée à Active Directory".
  3. Active les mises à jour dynamiques sécurisées uniquement.
  4. Crée un enregistrement CNAME intranet pointant vers le nom du serveur.
  5. Teste la résolution depuis un poste client avec nslookup intranet.cabinet.local.

Quiz de validation — Semaine 6

4 questions
1. Quel conteneur permet d'appliquer des GPO ciblées à un sous-ensemble d'utilisateurs ?
Les GPO se lient à des OU pour un ciblage précis, contrairement au domaine qui s'applique plus largement.
2. Quel type de groupe sert uniquement à la messagerie, sans permissions ?
Les groupes de distribution servent aux listes de diffusion email, pas au contrôle d'accès.
3. Quel est l'avantage principal du DNS intégré à AD ?
Les zones intégrées à AD se répliquent automatiquement avec l'annuaire, sans transfert de zone manuel.
4. Dans l'étude de cas hôtelière, pourquoi une délégation limitée à chaque OU plutôt que des comptes admin domaine ?
Un compte compromis avec des droits limités à une seule OU représente un risque bien moindre qu'un compte admin domaine.

7.1 — L'ordre d'application des GPO : LSDOU

Quand un utilisateur ou un ordinateur se connecte, Windows applique les GPO dans un ordre précis, chaque niveau pouvant écraser le précédent :

Fig. 7.1 — Ordre LSDOU (Local → Site → Domaine → OU), le dernier niveau gagne en cas de conflit

Deux paramètres peuvent inverser ce comportement : Bloquer l'héritage (sur une OU) empêche les GPO des niveaux supérieurs de s'appliquer, et Appliqué / Enforced (sur une GPO) force son application même si l'héritage est bloqué plus bas.

7.2 — Familles de paramètres GPO

  • Paramètres de sécurité — stratégies de mot de passe, verrouillage de compte, droits utilisateurs, pare-feu Windows
  • Modèles d'administration — configuration fine des fonctionnalités Windows et des applications Microsoft (Edge, Office)
  • Scripts — exécution automatique de scripts au démarrage, à l'arrêt, à l'ouverture/fermeture de session
  • Préférences — mappage de lecteurs réseau, imprimantes, variables d'environnement
Security Baseline (base de référence de sécurité)

Ensemble de GPO préconfigurées par Microsoft représentant les réglages de sécurité recommandés pour un rôle donné. Le Security Compliance Toolkit (gratuit) fournit ces baselines prêtes à importer.

📁 Étude de cas — Usine

Restriction logicielle sur les postes de supervision de production

Contexte : Une usine possède des postes Windows dédiés à la supervision d'automates (SCADA). Ces postes ne doivent exécuter que le logiciel de supervision — aucune installation, aucun navigateur, aucune clé USB non autorisée.

Solution GPO : une OU dédiée Postes-Production avec une GPO appliquant : liste blanche AppLocker n'autorisant que l'exécutable de supervision signé, désactivation des ports USB de stockage de masse via stratégie de restriction des périphériques, et GPO marquée Enforced pour empêcher tout contournement local.

Pourquoi si strict ? Un poste de supervision compromis peut avoir un impact physique direct sur la production — le principe de sécurité "tout est interdit sauf ce qui est explicitement autorisé" (liste blanche) prime sur la liste noire, plus permissive.

Laboratoire guidé — Configuration DHCP en haute disponibilité

Outil : Server Manager, 2 VM serveur · Durée : 40 min
  1. Installe le rôle DHCP sur un second serveur.
  2. Sur le premier serveur DHCP, ouvre la console DHCP → clic droit sur l'étendue → Configurer l'basculement.
  3. Choisis le mode Basculement partagé (Load Balance) ou Actif-Passif (Hot Standby) selon le besoin.
  4. Définis le pourcentage de répartition de charge (souvent 50/50 pour du load balance).
  5. Vérifie sur les deux serveurs que l'étendue est répliquée avec Get-DhcpServerv4FailoverStatistics.
  6. Simule l'arrêt du serveur principal et vérifie que le secondaire continue à distribuer des baux.

Laboratoire guidé — Mise en place du service de fichiers (DFS)

Outil : Server Manager · Durée : 35 min
  1. Installe le rôle Services de fichiers et de stockage → Espaces de noms DFS.
  2. Crée un nouvel espace de noms \\cabinet.local\Partages.
  3. Ajoute un dossier cible pointant vers un partage local (ex. \\SRV01\Compta).
  4. Depuis un poste client, accède à \\cabinet.local\Partages\Compta et vérifie l'accès transparent.

Laboratoire guidé — Sauvegarde et restauration Windows Server Backup

Outil : Windows Server Backup · Durée : 30 min
  1. Installe la fonctionnalité Windows Server Backup.
  2. Lance une sauvegarde ponctuelle du serveur complet vers un disque dédié.
  3. Une fois terminée, simule la suppression d'un fichier important dans un partage.
  4. Utilise l'assistant de restauration pour récupérer uniquement ce fichier (récupération granulaire).
  5. Planifie ensuite une sauvegarde quotidienne automatique.

Quiz de validation — Semaine 7

4 questions
1. En cas de conflit, quel niveau GPO l'emporte selon l'ordre LSDOU ?
Le dernier niveau appliqué (l'OU la plus proche) l'emporte, sauf blocage d'héritage ou GPO forcée.
2. Que fait l'option "Enforced" (Appliqué) sur une GPO ?
Enforced outrepasse le blocage d'héritage — utile pour imposer des règles de sécurité incontournables.
3. Dans un basculement DHCP en Load Balance, que se passe-t-il si un serveur tombe ?
C'est précisément l'intérêt de la haute disponibilité : continuité de service sans intervention.
4. Pourquoi l'usine choisit-elle une liste blanche (AppLocker) plutôt qu'une liste noire pour ses postes de supervision ?
Sur un poste critique, on préfère un modèle "tout interdit sauf autorisation explicite" plutôt que l'inverse.

8.1 — DFS : espace de noms et réplication

DFS comporte deux composants complémentaires :

DFS-N (Namespace)

Regroupe plusieurs partages dispersés sur différents serveurs sous un seul chemin logique unifié (ex. \\cabinet.local\Partages), transparent pour l'utilisateur.

DFS-R (Replication)

Réplique le contenu d'un dossier entre plusieurs serveurs, pour la redondance ou pour rapprocher les données des utilisateurs sur plusieurs sites.

Fig. 8.1 — Espace de noms DFS unifiant deux serveurs de fichiers

8.2 — Quotas et gestion du stockage

Le File Server Resource Manager (FSRM) permet de définir des quotas par dossier ou utilisateur (limite souple avec alerte, ou stricte avec blocage), ainsi que des filtres de type de fichiers pour interdire certains formats (ex. exécutables sur un partage de documents).

8.3 — Bureau à distance (RDS) et surveillance

Les Services Bureau à distance (RDS) permettent à plusieurs utilisateurs de se connecter simultanément à un serveur pour y exécuter des applications à distance — utile pour centraliser un logiciel métier sans l'installer sur chaque poste.

Pour la surveillance :

  • Observateur d'événements — journaux Système, Application, Sécurité ; essentiel pour diagnostiquer pannes et incidents de sécurité
  • Moniteur de performances (Perfmon) — suivi en temps réel ou historique du CPU, RAM, disque, réseau ; permet de détecter une dérive avant la panne
📁 Étude de cas — PME (bilan du module)

Infrastructure complète du cabinet comptable

Bilan : Le cabinet dispose maintenant d'un contrôleur de domaine avec DNS intégré, d'OU structurées avec délégation, de GPO de sécurité, d'un espace de fichiers DFS avec quotas, de sauvegardes automatisées et d'un accès RDS pour le logiciel comptable central.

Surveillance mise en place : un tableau de bord Perfmon basique surveille l'espace disque et la charge CPU du serveur, avec une alerte email si le disque dépasse 85% d'occupation — anticipation plutôt que réaction.

Laboratoire guidé — Configuration RDS (Bureau à distance)

Outil : Server Manager · Durée : 40 min
  1. Installe le rôle Services Bureau à distance (déploiement rapide, session-based).
  2. Ajoute le serveur comme hôte de session RDS.
  3. Publie une application (ex. Calculatrice, pour le test) via RemoteApp.
  4. Depuis un poste client, connecte-toi via le client Bureau à distance et lance l'application publiée.
  5. Vérifie la limite de sessions simultanées configurée.

Laboratoire guidé — Durcissement sécurité (Security Baseline)

Outil : Security Compliance Toolkit · Durée : 30 min
  1. Télécharge la Security Baseline correspondant à Windows Server 2022.
  2. Importe les objets GPO fournis dans la Gestion des stratégies de groupe.
  3. Lie la baseline à l'OU des serveurs (avec prudence — teste d'abord hors production).
  4. Compare les paramètres appliqués avant/après avec gpresult /h rapport.html.

Laboratoire guidé — Surveillance (Observateur d'événements / Perfmon)

Outil : outils natifs Windows Server · Durée : 30 min
  1. Ouvre l'Observateur d'événements, filtre le journal Système sur les erreurs des 7 derniers jours.
  2. Crée une vue personnalisée regroupant les événements critiques de sécurité (échecs d'authentification).
  3. Ouvre le Moniteur de performances, crée un ensemble de collecteurs de données (CPU, mémoire, disque).
  4. Configure une alerte déclenchée si l'espace disque libre descend sous 15%.

Quiz de validation — Semaine 8

4 questions
1. Quel composant DFS unifie plusieurs partages sous un seul chemin logique ?
DFS-N crée l'espace de noms unifié ; DFS-R gère la réplication du contenu entre serveurs.
2. À quoi sert RemoteApp dans RDS ?
RemoteApp permet à l'utilisateur de lancer une seule application distante, qui s'affiche comme une fenêtre locale.
3. Quel outil natif Windows Server permet de suivre le CPU/RAM/disque en continu ?
Perfmon collecte des compteurs dans la durée et permet d'historiser les tendances, contrairement au Gestionnaire de tâches (instantané).
4. Pourquoi le cabinet comptable configure-t-il une alerte à 85% d'occupation disque plutôt qu'à 100% ?
Une bonne surveillance est proactive, pas réactive — on veut être alerté avant que le disque soit plein.
